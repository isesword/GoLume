# Narrow explicit Parquet-to-bounded Decimal terminal

`LazyFrame.CollectDecimalBounded(ctx, key, value, options)` is a dedicated terminal over a pre-aggregation row plan. It composes CollectBatches, borrowed typed Int64/Decimal128 chunks and the existing fixed-256-row engine input. It does not change ordinary GroupBy/Agg, Collect, Auto, PreparedQuery aggregate dispatch or their previous unsupported-plan errors. It is not a generic Lazy or Source adapter.

## Source and logical admission

Before optimization or opening a reader, the terminal checks the original plan:

- At most 16 nodes, exclusively Scan, Filter and direct column Projection. Sort, TopK, Limit, aggregation, joins, windows, prefix operations and computed/renamed projections are rejected even if an optimizer could remove them.
- The underlying Scan must contain a concrete `*source/parquet.Source`. Arrow records, arbitrary/custom Source implementations and wrappers are rejected. Their retained memory is not established by the Parquet decoder accounting contract. The single-worker pipeline can directly forward a source, so an exchange charge cannot be assumed to cover arbitrary upstream ownership.
- The private original source must have at most 64 row groups and must not be a caller-created pushdown clone, even if its visible Stats/Schema were narrowed to zero rows or fewer columns. A new concrete-source read-only admission method checks allParts/baseSchema/allBindings without creating large copies before Prepare can allocate partition metadata. The original source schema must contain 1..8 plain scalar Int64/native Decimal128 fields, with bounded names (1..128 bytes), no nested children or dictionary domains. Projecting away an unsupported original field does not circumvent this check. Native Decimal metadata is validated.
- All filter predicates combined have at most 64 AST nodes. Accepted value nodes are direct Column, Int64Literal, BoolLiteral and Decimal128Literal; operators are GT/GE/LT/LE/EQ, And/Or, Not, IsNull and IsNotNull. Other expression forms, including pointer-form nodes, are rejected. Normal binding still checks operand types and referenced columns.
- The selected key must remain visible Int64 and value visible native Decimal128, with different names. Terminal Select(key,value) is appended after validation. Existing optimizer dependency propagation retains filter-only columns until their actual filter is evaluated; no filter is bypassed by the terminal.

The session pipeline must have exactly one worker and at most 65,536 rows per source morsel. The terminal supplies fixed byte limits: target and maximum morsel bytes are 1 MiB and maximum in-flight bytes 8 MiB. It does not provide an unbounded default batch size. A single delivered reader batch is also checked at 65,536 rows. The N32/33 row/batch/run limits apply to surviving rows fed into the engine; these are not limits on all rows scanned and filtered out upstream.

## Exact shared-budget composition

`DecimalBoundedTerminalOptions` takes a positive finite `Budget *memory.QueryBudget` and positive finite `Store *memory.QuerySpillStore`. Both are explicitly borrowed. Callers can obtain a query budget with `Engine.BeginQueryMemory` and construct a finite store with `memory.NewQuerySpillStore`. They must keep both alive until result Close, including all failed-delete retries, completes. The terminal never closes either resource. A context already carrying a different QueryBudget is rejected, rather than silently merging accounting roots.

The same query pointer is inserted into the CollectBatches context and passed as the engine's Manager. The returned reader is explicitly verified to have exactly that budget and `ownedBudget=false`. PreparedDataFrame.acquireQueryMemory calls Engine.AcquireQueryMemory, which borrows the context budget even when it was created under a different engine. The admitted pipeline paths select context-query operator managers explicitly: scanReadOptions supplies SourceScan, the Parquet decoder uses that manager, Filter uses query-owned evaluation/selection/output budgets, direct Project uses the context query, and the admitted single-worker path does not create a parallel exchange. No parallel independent engine budget is used for these live buffers.

This accounts for the complete simultaneously live GoLume decoded source vectors and decoder scratch, filter child/evaluation/compacted output, and the engine's fixed input, resident state, merge state, codecs, result buffer and file metadata. The adapter does not charge only the 256 copied rows while ignoring the rest of a borrowed source batch. A source batch and all required owner leases stay alive while the adapter feeds its successive 256-row slices into engine aggregation. Only after all those slices are consumed does reader.Next expire the old view and advance.

The terminal additionally reserves its wrapper/adapter sizes plus a fixed 256 KiB allowance before opening the reader, covering bounded adapter/view/chunk metadata overlap and preparation-time partition/plan copies under the 64-original-partition, eight-field and bounded-plan limits. This retained conservative reservation is not a measured RSS total. This is not an RSS bound or certification of all source-private memory. Parquet file/Arrow codec/page/dictionary metadata, prepared-plan/source metadata and general runtime overhead retain their pre-existing exclusions. In particular, declared page-size caps are not an aggregate Arrow memory quota. This narrow admission must not be advertised as total-process memory accounting or extended to arbitrary sources without a new proof.

## Output, options and lifetime

Options expose TableCapacity, Mode, AveragePrecision, AverageScale and AverageRounding from the explicit engine executor; input precision/scale are derived from the visible value column, not independently supplied. All three modes are supported: SUM/counts (default), AVG/counts and SUM+AVG/counts. Invalid options fail before opening the upstream reader. All final groups are precision-checked by the engine before a successful result is returned. Results are NULL-first, then signed Int64 ascending, regardless of input order.

The result exposes informational engine Stats, `Next(ctx)` returning an `*engine.DecimalBoundedOutputBatch`, and `Close(ctx)`. Output is borrowed only until the next Next or Close, including EOF and failures. The wrapper retains the original execution context and rejects its subsequent cancellation before and after output construction. A different context QueryBudget, closed caller budget or underlying restore failure prevents publication and triggers cleanup. The engine's release-before-final-context-check barrier remains unchanged.

The engine owns the adapter and closes it once it reaches its terminal return. Adapter Close closes the BatchReader/one-shot prepared plan; because the reader borrowed the query budget, upstream EOF and Close do not invalidate budget reservations needed by later spill merges, finalization or result.Next. The result retains its budget reference and the engine file owner until Close succeeds. Reader errors, engine errors, input-close errors, overflow and cancellation preserve their original errors.Is/errors.As identity through wrapping/joining.

On failure the wrapper cleans generated files. If deletion fails, a nonnil cleanup-only result and joined error retain the retryable engine owner and wrapper lease. Result.Close retries only its generated files and invalidates output; it never closes or deletes unrelated caller-store objects. Failed cleanup must not be followed by premature caller budget/store closure. Once generated-file cleanup succeeds the terminal lease is released. Then callers may close their own store and query budget. Their Close policies are external to this terminal, not silently replaced or claimed retryable here.

## Deliberate boundary

This is public composition of a constrained Parquet Lazy row pipeline with the explicit bounded engine executor. It is not support for generic retained Arrow input, arbitrary Sources, computed projection, normal grouped Lazy terminal dispatch or automatic strategy selection. Existing N29-N33 scheduler, encoding and arithmetic files are unchanged. The only source-package addition is decimal_bounded_admission.go; existing Parquet source implementation files remain unchanged.
