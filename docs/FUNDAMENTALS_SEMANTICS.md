# Fundamentals semantic baseline

This baseline separates **observed reference behavior**, **existing compatibility
contracts**, and **new implementation requirements**. It is not a claim that all
planned operations already exist. Existing behavior was inspected at
`895c2bc8df5761e04b4e30472972f0ccd7577af8`. Changes to this document's implementation
status must be supported by the corresponding API and execution tests.

## Reproducible reference

`testdata/fundamentals/polars-1.35.2.json` contains observations from **Polars
1.35.2**, generated by `scripts/fundamentals_polars_oracle.py`. The generator
rejects another version. Install that exact version in an isolated Python
environment, then run:

```sh
python scripts/fundamentals_polars_oracle.py
python scripts/fundamentals_polars_oracle.py --check
```

The JSON encodes NaN and infinities as `"NaN"`, `"+Inf"`, and `"-Inf"`; these
are floating special values, not string results. JSON null denotes missingness.
Negative zero is retained as `-0.0`. Errors contain exception class names rather
than unstable message text. Record dtypes as well as values: matching numerical
values alone does not establish API compatibility.

Normal Go tests do not require Python. `aggregate/fundamentals_semantics_test.go`
consumes the committed reference to validate the existing int64 state API for
empty, all-null, and mixed inputs, including alternate partition merge and Reset.
The sole value exception in this test is explicitly named below. The broader
oracle is input for new operator tests, not a substitute for testing GoLume's
execution modes. Regeneration checks the reference, not GoLume equivalence.

## Existing compatibility contracts

- SQL null uses validity bits, never a NaN sentinel. Count-values ignores null;
  count-rows includes it. Empty counts return zero.
- Existing int64 SUM, MIN, MAX, and AVG return null if no valid value was seen.
  **Keep SQL empty/all-null SUM null**, although Polars returns typed zero.
- Existing count states expose int64 values; Polars default index/count dtype is
  UInt32. Do not narrow an existing GoLume count merely to match this oracle.
- Existing integer SUM wraps in its output integer width. Polars int64 and uint64
  sums also wrap. Existing `AvgState` and int64 vector averaging accumulate an
  int64 sum before division; overflow can produce an incorrect mean. This is a
  legacy limitation, **not a desired average contract**. A separately documented
  typed mean implementation should avoid overflowing the sum used for its mean.
- Explicit numeric casts are checked and preserve the target physical width.
  Existing float64-to-float32 casts reject infinity and out-of-range magnitudes;
  this is stricter than Polars. Existing general binary numeric coercion widens
  floats to float64 and most integer pairs to int64; mixed uint64 uses float64.
  Adding math functions must not silently rewrite that existing coercion policy.
- At the inspected revision, grouped aggregation accepts one shared int64 value
  column and one/two supported key columns; the engine rejects a zero-key global
  query. Extension work must establish and test its new support separately.

## Observed Polars aggregate semantics

- Null is skipped by SUM/AVG/MIN/MAX, but NaN counts as a value. SUM/AVG propagate
  NaN; MIN/MAX ignore NaN when a finite value is present. Opposite infinities sum
  to NaN. A null key forms a group, including all-null value groups.
- SUM widens Int8/Int16/UInt8/UInt16 to Int64. Int32/UInt32/Int64/UInt64 and float
  SUM preserve their dtype. MIN/MAX and FIRST/LAST preserve the input dtype.
  AVG/VAR/STD return Float64 for integer input and preserve Float32 input.
- Global reduction of an empty typed column still has one result row; empty
  MIN/MAX/AVG are null, SUM is zero, COUNT and LEN are zero. An empty grouped
  input has no groups. GoLume's new global path must emit one result row with
  its SQL-compatible null SUM, not fabricate a group in grouped execution.
- Floating aggregate merge order can change rounding. Compare finite results
  with operation-appropriate absolute/relative tolerances, while comparing null,
  NaN, infinity signs, integer values, dtype, and cardinality exactly. Sorting
  output groups before comparison does not authorize changing ordered operators.

## Observed string-to-number parsing

- Decimal integer syntax accepts a leading plus; unsigned `-0` is invalid.
  Surrounding whitespace is not trimmed. Fractions/exponents are invalid for
  integer destinations. Empty strings, hex, and underscores are invalid.
- Float parsing accepts decimal fractions/exponents and case-insensitive NaN,
  Inf, and Infinity spellings. Signed infinity is accepted. Hex float syntax and
  underscores are rejected.
- Polars strict casts fail on invalid syntax or integer overflow; non-strict
  casts return null for the failing element and preserve valid neighbors/nulls.
- **Reference difference requiring an explicit GoLume policy:** Polars accepts
  decimal floating overflow as infinity (`1e999`; Float32 `1e40`) and underflow
  as zero. Existing checked GoLume casts need not adopt overflowing parses.
  Strict and TryCast must share one grammar/range classifier; TryCast must not
  suppress cancellation, memory-budget failures, or malformed structural input.

## Observed math semantics

- ABS preserves dtype; minimum signed int64 ABS wraps to itself. Integer FLOOR
  and CEIL are identity operations preserving dtype. ROUND defaults to ties-even
  (`-2.5 -> -2`, `-1.5 -> -2`, `1.5 -> 2`, `2.5 -> 2`). Floating signed zero is
  observable; nulls remain null and NaNs remain valid NaNs.
- Floor division rounds toward negative infinity. Modulo follows the divisor's
  sign (`-5 % 2 = 1`, `5 % -2 = -1`). Integer division/modulo by zero yields null.
  Float floor division by zero yields IEEE infinity/NaN; float modulo by zero
  yields NaN. Int64 minimum divided by -1 wraps; its remainder is zero.
- Floating modulo with an infinite divisor yields NaN, even for finite dividend.
  Finite floor division by infinite divisor yields signed zero; infinite over
  infinite yields NaN. Polars `1e20 % 3` and `-1e20 % 3` return zero due to its
  arithmetic formula. A more accurate remainder implementation must document
  that difference instead of claiming exact reference parity.
- SQRT of negative values and LOG of negative values yield NaN; SQRT(-0) retains
  -0, LOG(±0) is -Inf. Floating POW supports negative and fractional exponents;
  integer POW with a negative integer exponent errors. Integer positive powers
  wrap on overflow (Int64 `2**63` is minimum int64; Int64/UInt64 `2**64` is zero).

## Observed statistics and ordered operations

- VAR/STD ignore nulls, include NaNs, and use `n - ddof`. Empty inputs return
  null; singleton ddof=0 returns zero, ddof=1 or 2 returns null. `[1,3]` has
  population variance 1 and sample variance 2. NaN propagates.
- FIRST/LAST include boundary nulls rather than searching for non-null values.
  N_UNIQUE counts null once and repeated NaNs once: `[NaN,NaN,null,2]` has 3.
- Exact median/quantile skip nulls. For `[1,3]`, median is 2; q=.25 gives 1 for
  nearest/lower/equiprobable, 3 for higher, 2 for midpoint, 1.5 for linear.
  NaNs sort above finite values: `[NaN,NaN,null,2]` has NaN median, q=.25 lower
  and equiprobable give 2, while nearest/higher/midpoint/linear give NaN.
  Choose and document interpolation explicitly; an approximate sketch is not an
  exact quantile implementation. Empty median/quantile return null.
- SHIFT preserves length/order, fills exposed positions with null, and supports
  positive/negative offsets. DIFF preserves length by default and yields null
  when either endpoint is null. FILL_NULL and FILL_NAN are separate operations:
  filling null must not replace NaNs, and filling NaN must not replace nulls.

## Required execution and SIMD gates

Every new supported type/operator needs typed boundary tests plus selected rows,
nullable/all-valid, empty input, repeated execution, cancellation, and ownership
coverage. Aggregates additionally need global/grouped, cross-batch null keys,
multiple input columns, merge/parallel partitioning, sorted/resident/spill result
agreement, and reservation release after success/error. Unsupported paths must
fail explicitly, not silently fall back to an unbudgeted materialization.

Scalar is the semantic reference. SIMD must preserve validity, domains, integer
wrap/checked behavior, NaNs/infinities, and documented signed zeros. A candidate
is not enabled solely because vector instructions exist: retain architecture-
specific dispatch and measured gates. No cross-architecture performance claim
follows from the Polars oracle or a single-host microbenchmark.
