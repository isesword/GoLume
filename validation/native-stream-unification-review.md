# Native stream unification review

**WIP checkpoint: not ready for merge or complete performance acceptance.**
Correctness/build validation and independent review passed for the included code.
The prepared W4 performance gate remains unmet (last formal comparison +67.19%).
The final shared-workspace comparison also does not prove a strict 3% bound.
Experimental producer filtering, hash hot-loop, layout, cache and double-wave
changes are not included. See the individual results and limitations below.

Baseline: `965e0b33b14f6f24be52616493237038c65e0365`, branch
`fix/foundation-cse-memory-lifecycle`. This change intentionally breaks APIs;
see [migration guide](../docs/STREAM_MIGRATION.md).

## Architecture and review scope

- Source requires incremental BatchStream. Reader, whole-partition fallback and
  public Parquet Reader are removed, rather than wrapped.
- Engine record results and lazy DataFrames use the same physical aggregate
  implementations. The old direct/radix/workspace execution tree is removed.
- Joins use one columnar physical path. Partition-relative row-reference APIs
  and redundant lazy aliases are removed.
- Explicit partition subsets must be honored exactly or rejected. Global
  operators no longer advertise a subset method that ignores the request.
- Parquet uses page-bounded bulk string cursors and copies only admitted output.
  Query-owned vectors, scratch and headers are reused across compatible row
  groups. Borrowed decoder references are cleared before opening another group.
- Compressed and uncompressed page guards reject oversized pages before body
  allocation. They are not a shared process RSS limit.

Independent review covered ownership, resource failure paths, partition order,
nullable predicates, output growth, external budgets and removed API callers.
It found and prompted fixes for narrow literal truncation in both bitmap/fused
predicates, result backing-array reservation lifetime, sorted string growth
old/new overlap, actual execution budget compatibility, and stale documentation.
Tests use independent literal oracles rather than comparing two affected paths.

## Resource limits

In the audited native scan, aggregate, projection and Filter paths, managed
decoded buffers, scratch, state and owned output are reserved before allocation. Growth accounts for live old and new buffers.
Failure, EOF, cancellation and Close release owned references and reservations.
Immutable Arrow/in-memory input is borrowed, not recharged as a new allocation.
Materialized Result rows are charged during collection and transferred to caller
ownership on successful return; retained caller results are outside later query
budgets.

Arrow pages/dictionaries, codec internals, O(columns) metadata (including inline
one-row cursor slots), Go object/map overhead, runtime and GC retention
remain separate from managed reservations. The allocator interface has no
recoverable failure return, so no panic-based quota adapter was introduced.
Default per-page compressed/uncompressed guards are 8 MiB each, independently;
multiple columns and codecs can retain more than one page. This is not an RSS
or aggregate decoder-memory guarantee. A rare near-budget string value can
require replaying its string chunks from already-emitted rows with cancellation
checkpoints; this trades extra decoding for bounded owned buffers.

## Initial full validation and performance checkpoint

Before the parallel-aggregation follow-up, the complete repository
`scripts/validate.sh` passed: GoDoc, generated SIMD checks, kernel registry,
SIMD structure, complete ordinary/SIMD tests, forced SIMD-off/128/256/512 tests,
Linux amd64 build, race suite, vet and the synthetic-fixture demo. Additional
source/in-memory/pipeline/expression race tests passed. Later code changes must
be revalidated; this checkpoint is not a claim about an untested final tree.

The first pinned, alternating 10 x 1-second engine comparison **failed the
performance acceptance gate**. Raw samples and median calculations are retained
in `native-unification-initial-{baseline,stream}.txt` and
`native-unification-initial-medians.json`. In-memory bitmap execution regressed
7–9%; the four-worker comparison regressed from 9.94 ms to 37.56 ms. The latter
compares the same prepared aggregate workload, mapping the removed
BenchmarkPreparedRadixW4 to BenchmarkPreparedStreamW4, not two identically named
algorithms. Parallel scanning alone did not parallelize predicate/hash
aggregation and added exchange copies. These failed measurements must not be
replaced by unrelated string-scan gains or treated as passing evidence.

An auxiliary Parquet source comparison used eight alternating 200 ms samples,
GOMAXPROCS=1, 65,536-row groups and 131,072 full-scan rows. This is supporting
measurement, not a substitute for the required 10 x 1-second performance gate:

- Mixed-string native full scan: 46.18 -> 21.85 ms (-52.68%, p<0.001).
- Mixed-string first batch: 727.5 -> 522.2 microseconds (-28.22%).
- Numeric full scan: 5.444 -> 5.028 ms (-7.65%, p=0.021).
- Numeric first batch: 226.2 -> 230.9 microseconds (+2.11%, p=0.328).
- Mixed-string Go allocations: 2,928,862 -> 2,762,206 B/op (-5.69%);
  allocation count increased 1.48%. Numeric B/op decreased 4.81%.
- Mixed-string managed peak: 233,862 bytes, below its 256 KiB budget. Charged
  cursor headers increased this peak 19.1%; numeric peak stayed 65,152 bytes.

Raw auxiliary samples are in `native-parquet-scan-aux-{baseline,current}.txt`.
Legacy-only baseline rows are historical context, not a current execution path.
Geometric means across unequal benchmark sets must not be interpreted as gains.

The subsequent **10 x 1-second** source gate superseded the auxiliary numeric
result: mixed-string full scan improved 52.33% (50.352 -> 24.001 ms), but numeric
full scan regressed 9.86% (5.551 -> 6.098 ms, p=0.009). Numeric first-batch latency
was unchanged (245.8 -> 245.9 microseconds, p=0.796). This first formal source gate
therefore failed; targeted profiling is required, not cherry-picking the shorter
auxiliary result. Samples are preserved in
`native-parquet-initial-gate-{baseline,current}.txt`.

After profiling identified per-value validity writes, the numeric decoder now
accumulates validity in 64-row words. Independent NULL/tail/reuse oracles and
package/race tests passed. The fresh-build final **10 x 1-second**, alternating
source gate passed all four cases:

- Mixed first batch: 775.3 -> 542.5 microseconds (-30.02%).
- Mixed full scan: 48.279 -> 22.277 ms (-53.86%).
- Numeric first batch: 236.6 -> 233.9 microseconds (-1.14%, p=0.739).
- Numeric full scan: 5.421 -> 4.917 ms (-9.30%, p<0.001).
- Mixed full-scan B/op decreased 5.77%, while allocation count increased 1.48%.
- Numeric B/op decreased 4.78%. Managed peaks remained 233,862 and 65,152 bytes,
  respectively, both below 256 KiB.

Final source samples: `native-parquet-final-{baseline,current}.txt`. These
results establish the source-only gate, not the separate engine aggregation
performance gate. Earlier failing evidence remains above and in its raw files.

## Prepared-state reuse diagnostic (not a passing gate)

A separate scratch-only experiment retained group tables and fixed
wave/scatter/predicate scratch under one explicitly live 128 MiB budget across
iterations. Source scans remained fresh. It checked selected rows, groups,
checksum, stable retained bytes, and zero charged bytes after Close. This is an
upper-bound performance experiment, not production cross-query accounting or a
cache implementation.

Three alternating 1-second samples gave these medians:

- Previous prepared W4: 10.082 ms, approximately 29.79 MB/op.
- Native fresh W4: 17.012 ms, approximately 53.71 MB/op.
- Native retained-state experiment: 15.073 ms, approximately 32.41 MB/op,
  retaining 20,885,808 charged bytes between iterations.

Retention improved the native sample by about 11.4%, but remained 49.5% slower
than the previous prepared path. It does not justify adding a production cache
as the solution to the failed performance gate. Remaining execution costs need
profiling. Raw samples: `native-aggregation-reuse-diagnostic.txt`. The experiment
source is not part of production code; three samples are diagnostic evidence,
not the required final 10-sample acceptance run.

## Bounded prehashed contiguous-kernel experiment

One final scratch-only experiment removed all-true selection iteration for
already packed I32 batches and reused classification hashes for table lookup.
It retained the shared insertion and aggregate-state semantics, reserved both
additional hash arrays before allocation, and reduced the wave row cap to
account for that storage. Eight layouts, NULL combinations, tails, repeated
growth/reset, native partition/wave boundaries and Close-to-zero checks passed.

Three paired 1-second retained-state samples did not establish a benefit:
14.906 ms baseline median versus 15.219 ms experimental median (+2.1%; too few
samples for a formal gate). Charged retained storage increased from 20,885,808
to 25,209,136 bytes. The experiment was not adopted, no fresh-state benchmark
was needed, and further speculative variants were stopped. Raw samples are in
`native-aggregation-prehash-diagnostic.txt`.

The production tree remains the fully validated native implementation. Its old
prepared W4 performance acceptance remains unresolved. A new hash/state-layout
or bounded local-aggregation/merge design requires a separate, evidence-led
implementation phase; these diagnostics are not a waiver of the existing gate.

## Frozen production performance matrix

Fresh SIMD binaries from exact commit 965e0b33b14f6f24be52616493237038c65e0365
and the validated production tree were measured in ten alternating 1-second
pairs. Single-worker tests used one fixed CPU/GOMAXPROCS=1; W4 used four fixed
CPUs/GOMAXPROCS=4. Fixtures were identical on both sides. Results:

- Prepared W4: 10.04 -> 16.78 ms, +67.19%, p<0.001. Allocation volume:
  28.41 -> 51.22 MiB/op, +80.29%. This fails the performance gate.
- In-memory direct-fused SIMD, 50% selection: 7.896 -> 8.291 ms,
  +5.01%, p=0.035. This also fails the 3% gate.
- In-memory direct-fused scalar: 7.964 -> 8.251 ms, +3.60%, p=0.247.
  The change is not statistically significant; it is not evidence of meeting
  the 3% threshold.
- In-memory bitmap scalar/SIMD improved 16.08%/13.13%, respectively.
- Single-worker Parquet bitmap improved 19.37%.
- Single-worker Parquet fused: 42.65 -> 40.32 ms, no significant change,
  p=0.075.

All benchmark correctness assertions passed. The matrix did not measure other
selection ratios or cold preparation. Raw samples and name-mapped benchstat are
`native-aggregation-frozen-{baseline,current,benchstat}.txt`. Individual failing
cases remain blockers; a geometric mean must not conceal them.

The validated source snapshot is preserved separately before subsequent layout
prototypes. The next design phase keeps experiments isolated: shared SUM/COUNT
state interleaving and packed I32 key/generation probe headers are independently
measured, with unchanged managed bytes and SQL NULL/ownership semantics. Neither
is adopted merely because it is plausible; each needs repeatable end-to-end
benefit and full regression verification.

## Independent layout prototypes rejected

Two isolated layout experiments preserved managed bytes and passed ordinary,
race, SIMD, vet and independent static review. SUM/COUNT interleaved state kept
17 bytes per slot; packed I32 key/generation headers kept 8 bytes per slot.
Capacity/probe diagnostics excluded a load-factor confound: all 256 shards had
2048 slots, distinct groups ranged 788–939, and canonical old/native probe
positions and counts matched (638,957 total probes for 472,475 rows).

Five alternating 1-second samples for each independent variant gave W4 medians:
16.40 ms frozen, 16.73 ms interleaved state (+2.04%, not significant), and
17.71 ms packed header (+8.01%, p=0.032). Neither significantly improved either
fused mode. Both failed the predeclared 5% benefit criterion and were rejected;
they were not combined or copied to production. Raw files are
`native-layout-{frozen,state-cell,probe-header}.txt` and `native-layout-benchstat.txt`.
The next investigation compares actual hot-loop and execution-phase costs rather
than adopting another unproven storage variation.

## W4 execution-phase diagnosis

Test-only coarse phase instrumentation distinguished wall time, summed worker
elapsed time and overlap. Instrumented old/native-fresh/native-retained medians
were 9.20/15.38/13.36 ms, not replacements for the formal uninstrumented gate.
Native serial predicate plus exclusive compaction/append consumed 5.40/4.56 ms
in fresh/retained executions. Native hash wall was 4.77–4.80 ms versus old
2.13 ms; summed worker elapsed also increased. Only 0.55 ms of retained decode
overlapped its 7.24 ms of aggregation flushes.

A separate controlled diagnostic held scan rows at 64K, in-flight allowance at
128 MiB and budget at 256 MiB for all variants. These are deliberately different
from the original gate's resource settings. Across 120 measurements per mode:

- 128K wave: four flushes; fresh/retained 17.48/16.00 ms; retained hash 6.59 ms.
- 256K wave: two flushes; 15.71/14.10 ms; retained hash 4.89 ms.
- 512K wave: one flush; 14.78/12.55 ms; retained hash 3.34 ms.

Maximum charged fresh peaks were 22,375,552 / 26,127,488 / 27,547,728 bytes;
retained peaks were 22,375,552 / 26,127,488 / 32,789,408 bytes. Fresh setup rose
from 0.39 to 1.23 ms at 512K. All exact-result and release assertions passed.
Repeated shard visits therefore have a measurable cost, but a larger wave alone
does not close the gap and these higher-budget results do not pass the gate.
The next causal prototype targets worker-local predicate/selected compaction
with shared budgeted ownership, while keeping the original wave and budgets.

## Shared 64-row fused-mask candidate passes its formal gate

The isolated candidate passes each borrowed 64-row predicate mask directly to
the existing typed selected-row aggregate kernel. It removes per-selected-row
callback dispatch without building a full-batch selection bitmap or introducing
another aggregate-state implementation. One stream-owned 8-byte mask is reserved
before allocation, reused synchronously and released on terminal cleanup.
Wide-literal fallbacks also obey logical Batch.Rows when backing slices are
longer. Ordinary/oracle/race/vet checks and independent static ownership review
passed before the final candidate binary was built.

Ten alternating 1-second comparisons against exact 965 produced:

- In-memory fused scalar: 8.272 -> 6.522 ms, -21.16%.
- In-memory fused SIMD: 8.007 -> 6.419 ms, -19.84%.
- Parquet fused: 42.27 -> 34.90 ms, -17.43%.

All three changes had p<0.001 and passed the timing gate. In-memory allocation
volume still increased from the old retained-workspace benchmark's 344 B/op to
48,984 B/op; query-owned state/metadata and ownership costs remain explicit.
Raw samples: `native-fused-mask-final-{baseline,mask,benchstat}.txt`.
This candidate is isolated pending integration with the separate shared
predicate logical-row boundary fix and renewed affected validation. It does not
resolve the independent prepared W4 performance blocker.

The approved fused-mask and shared predicate logical-prefix fixes were then
integrated into the production worktree. The complete `scripts/validate.sh`
passed again, including ordinary/SIMD suites, forced SIMD widths, race, vet,
generated checks and demo. A separate source checkpoint and SHA-256 manifest
were preserved before the next Filter/hash prototypes. The predicate regressions
also fail against the earlier frozen code with the expected bitmap-boundary
panic, confirming they cover an actual defect. This integrated checkpoint still
has the independently documented W4 performance blocker; no unproven Filter or
hash-kernel experiment is included.

## Shared no-grow hash-loop candidate remains unproven

An isolated I32 SUM/COUNT non-NULL batch specialization removes successful-row
calls, stops before an insertion actually needs growth, then uses the existing
reserve/grow/rebind path. State initialization shares the generic mathematical
transition. Capacities, probes, load factors and storage layout remain unchanged.
Independent static review and ordinary/SIMD/race/oracle/ownership checks passed.

Three uninstrumented paired 1-second samples suggested a W4 median improvement
of 7.08%, with essentially unchanged allocation volume. However, a separate
120-execution-per-variant fresh-query attribution check did not establish the
predeclared 10% hash-wall target: 4.717 -> 4.491 ms (-4.8%), summed callback
elapsed 16.662 -> 15.624 ms (-6.2%). Summed worker elapsed is not CPU time.
Blocks varied from -13.6% to +9.6%; unchanged phases also varied. Instrumented
total medians were 15.069 -> 15.326 ms. These diagnostics neither replace the
uninstrumented gate nor justify selecting only the favorable short sample.

The candidate remains isolated and is not combined with the Filter prototype.
All exact-result, original 256K-wave and release assertions passed. Smoke samples
are `native-hash-hotloop-{checkpoint,hotloop}-smoke.txt`. More controlled evidence
is required before adoption; the performance criterion has not been waived.

## Producer Filter experiment rejected; ownership fixes retained separately

Three paired W4 smoke samples suggested only 6.22% improvement, below the
predeclared 10% criterion. Allocation volume rose about 5.6% and charged peak
rose 26,127,488 -> 28,542,592 bytes. Independent phase attribution showed that
predicate plus exclusive append shrank 4.748 -> 0.713 ms, but exposed Next grew
2.140 -> 5.867 ms. Hash wall rose 4.783 -> 5.065 ms (+5.9%), and instrumented
median execution was effectively flat. The producer acceleration is rejected;
it is not combined with the unproven hash-loop candidate.

A separate correctness-only candidate includes the shared predicate workspace,
canonical Filter capacity/reservation/lifetime fixes and aggregate query-owner
guards. It excludes producer-input wrapping, dense-wave and producer diagnostics.
Independent review and complete scripts/validate.sh passed. The final ten-pair
ordinary comparison against the validated fused/row-bound checkpoint found no
statistically significant timing change, but does NOT prove a strict 3% bound:

- Fused scalar: 6.314 -> 6.304 ms, p=0.739.
- Fused SIMD: 6.248 -> 6.466 ms, +3.49%, p=0.218.
- Bitmap scalar: 6.177 -> 6.213 ms, p=0.796.
- Bitmap SIMD: 6.147 -> 6.368 ms, +3.60%, p=0.529.

Timing spreads reached 4–8%. Fused allocation count stayed 220; bitmap gained
three fixed owner/metadata allocations and 144 B/op. The included correctness
fixes close real admission/lifetime gaps; this WIP publication does not relabel
uncertain performance as a pass. Raw files are
`native-filter-correctness-{checkpoint,correctness,benchstat}.txt` and
`native-producer-filter-{checkpoint,filter}-smoke.txt`.

## Remaining design blocker

Existing traces were analytically replayed for an ideal two-buffer overlap of
the original frontend and hash stages, without extra Filter copying. Default
256K fresh-query median would still be approximately 12.45 ms. Even deleting
all exposed Next time gave an optimistic 10.95 ms, above the roughly 10.34 ms
acceptance target. The 128K replay with free Next remained about 11.82 ms.
Two 256K buffers fit the original reservation share, but memory feasibility is
not evidence of adequate speed. No double-wave implementation is included.

Meeting the old warm prepared benchmark while retaining the new bounded,
query-owned architecture remains a design-level task. Further work needs a
new measured hypothesis and explicit acceptance criteria; the current evidence
does not justify claiming completion or promising a fixed remaining duration.
